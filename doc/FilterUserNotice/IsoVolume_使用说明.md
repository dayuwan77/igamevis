# IsoVolume 等值面体提取 使用说明

## 1. 功能

`IsoVolumeFilter` 提取**标量值落在 `[lower, upper]` 区间内**的体网格，即**两层等值面之间的区域**。

- 对每个单元按标量做三分类：**完全在内**（保留）、**完全在外**（丢弃）、**与等值面相交**（裁剪细分，保留区间内部分）。
- 输入单元与等值面相交时会被细分成更小的单元，因此**输出单元数可能大于输入**（属正常裁剪行为）。
- 支持的单元类型：**规则体单元**（四面体 / 六面体 / 棱柱 / 金字塔，按原生单元表驱动裁剪）、
  **多面体**（按顶点的面扇分解为四面体后裁剪，输出为四面体）、
  **2D 面单元**（三角形 / 四边形 / 多边形，输出为三角形）、**二次四面体**、通用 Volume 体单元。
- 注意：**二次六面体 / 二次棱柱 / 二次金字塔、Lagrange 等单元不在支持范围** —— 与等值面相交的这类单元会被**静默跳过**（完全在内的仍会保留），结果可能不完整且无提示。
- 支持**时序数据（.pvd 等多帧数据）**按帧提取，并提供播放面板（见第 4 节）。

## 2. 调用方式

### 2.1 代码接口（C++）

```cpp
#include <IsoVolume/iGameIsoVolumeFilter.h>

auto filter = iGame::IsoVolumeFilter::New();
filter->SetInput(mesh);                                   // 体网格(UnstructuredMesh / VolumeMesh)，或 .pvd 等多帧容器
filter->SetIsoScalarData(array, lower, upper, dim);       // array: 点标量数组; lower/upper: 下/上阈值; dim: 取该数组的第几分量
filter->SetTimeStep(0);                                   // 可选: 时序数据取第几帧(从 0 开始，默认 0)
if (!filter->Execute()) { /* 执行失败 */ }
auto result = filter->GetOutputMesh();                    // UnstructuredMesh::Pointer
// 注: GetOutput() 返回 DataObject::Pointer, 需要时用 GetOutputMesh() 或自行 DynamicCast
```

参数说明：

| 参数 | 含义 |
|---|---|
| `SetInput(obj)` | 输入网格（`UnstructuredMesh`/`VolumeMesh`）或时序容器（`.pvd` 读入的 `DrawObject`）；需带**点标量** |
| `SetIsoScalarData(array, lower, upper, dim)` | `array`=点标量数组；`lower`/`upper`=下/上阈值；`dim`=选择该数组的第几分量（多分量数组用） |
| `SetTimeStep(n)` | 时序数据（`.pvd` 等）取第 `n` 帧（从 0 开始）；非时序数据忽略 |

### 2.2 GUI 调用

菜单 **算法处理 → 等值面体提取 (IsoVolume)**：

- **点属性数组**：选择要使用的点属性（支持多属性）；
- **标量分量**：选择该数组的分量（多分量数组可选）；
- **时间帧**：数据含**多帧**（帧数 > 1）时才出现，选择要提取的帧；
- **lower / upper**：区间上下限（打开面板时、以及切换数组/分量时，自动填该分量数据范围的 1/3~2/3 处，可改）。

## 3. 使用示例

完整示例见 `Examples/Filter/TestIsoVolume.cpp`（按相对路径 `./Models/...` 读取测试模型，因此需在 examples 的构建/运行目录下执行）。

```cpp
// 读取模型(相对路径，无需手动输入)
auto obj = iGame::FileIO::ReadFile("./Models/IsoVolumeTest_RadialShell.vtk");

// 取点标量数组
auto attrs = obj->GetAttributeSet()->GetAllPointAttributes();
auto array = attrs->GetElement(0).pointer;   // 简易写法; 实际使用建议按 GetName() 查找(见 TestIsoVolume.cpp)

// 提取 Radius ∈ [0.5, 0.9] 的等值体
auto filter = iGame::IsoVolumeFilter::New();
filter->SetInput(obj);
filter->SetIsoScalarData(array, 0.5, 0.9, 0);
if (!filter->Execute()) { /* 执行失败 */ }
auto result = filter->GetOutputMesh();
// result 即两层等值面之间的体网格
```

内置测试模型（`Examples/Models`）：

| 模型 | 说明 | 建议区间 |
|---|---|---|
| `IsoVolumeTest_RadialShell.vtk` | 标量=到球心距离，等值体为球壳（数据范围 [0.091, 1.732]） | `Radius` [0.5, 0.9] |
| `IsoVolumeTest_DoubleBlob.vtk` | 两个高斯团，等值体为两个分离区域（数据范围 [0.000045, 0.974]） | `BlobLevel` [0.7, 0.95] |

## 4. 时序数据（.pvd 等多帧数据）

### 4.1 支持范围

- `.pvd` 会被读取为**容器对象（`DrawObject`）**，其中保存时序元数据（每帧的文件路径）以及**第一个时间帧**的子网格；
- Filter 按 `SetTimeStep` 指定的**帧号**从时序元数据中解析出该帧的文件并读取，因此 `.pvd` 可直接作为输入；帧号越界时会被**钳制**到最后一帧（不报错）；
- GUI 在提取成功后会弹出 **「IsoVolume 时序播放」面板**（深色小面板；仅当数据含**多帧**（帧数 > 1）时出现）：

| 控件 | 作用 |
|---|---|
| **滑块** | 拖动浏览各帧；帧信息标签实时显示 `第 N / M 帧` 与 `时间 … · …点/…单元` |
| **◀ / ▶** | 上一帧 / 下一帧 步进 |
| **帧号输入框** | 直接跳到指定帧 |
| **▶ 播放 / ⏸ 暂停** | 自动逐帧播放（循环） |
| **✕** | 关闭面板 |
| **标题栏拖动** | 移动面板位置 |

### 4.2 缓存与性能

- **结果缓存**：每帧提取的**结果**会被缓存（最多 30 帧，按最近使用顺序淘汰；当前显示帧不被淘汰，瞬时最多 31 帧）。命中缓存时**不再重算**，帧信息标签会追加 `(缓存)`；
- **首轮较慢**：每个新帧都需要「读取该帧文件 + 裁剪」，数据大时单帧需要数秒，属正常；
- IsoVolume 面板**不缓存**原始的逐帧网格（只缓存提取结果）；但打开 `.pvd` 时**第一个时间帧**的网格会被读入并常驻内存（另外，动画面板的「动画缓存帧数」等功能会独立开启帧数据缓存）。

### 4.3 时序限制

1. **支持多分块帧**：同一帧由**多个分块**（并行分区，如 `xxx_0_0.vtu` / `xxx_0_1.vtu`）组成时，会**逐块提取后合并**为一个网格（分块互不重叠，等价于整体处理）；
2. **帧文件必须可达**：`.pvd` 中记录的是**文件路径**，若对应 `.vtu` 不存在或路径不可读，该帧会提取失败；注意多分块帧中若**只有部分分块**不可读，会**静默返回不完整结果**（仅当全部分块都失败才报提取失败）；
3. 除**第一个时间帧**（打开 `.pvd` 时即读入其子网格）外，其余帧**不会预加载**；只有被访问的帧才会读取其文件。

## 5. 注意事项

1. **需要点标量**：IsoVolume 按点取标量；如果数据只有**单元标量（cell data）**，请先做 **ConvertToPointData（转换为点数据）** 再用（菜单：算法处理 → 数据转换 (Convert) → 转换为点数据）。注意：Filter **只校验数组元素数 ≥ 点数**，**不检查它是点属性还是单元属性** —— 若把单元数组直接经 C++ 接口传入且其元素数 ≥ 点数，校验会通过，但结果是**错位的**（单元值被当作点值读取）。
2. **单分量 / 按分量**：IsoVolume 使用单分量标量；多分量数组需指定 `dim`（或在 GUI 里选「标量分量」），取值 `0…分量数-1`。越界无保护（仅 Debug 断言），**负值会被当作取该向量的模长**。
3. **建议体网格**：本 Filter 针对 3D 体单元设计；2D 面网格也能计算，但结果不是"体"，不建议用于结果验证。
4. **多面体支持**：多面体单元（如 Star CCM+ 网格）面/顶点数较多，其单元 id 列表长度可能超过
   固定栈缓冲上限（`IGAME_CELL_MAX_SIZE`）。IsoVolume 自身对多面体的读取已改为**指针式动态读取**
   （`GetCellIds` 指针重载 + `_GetCell` 多面体分支），可正常裁剪、提取；但多面体是
   **按面扇分解为四面体**后裁剪，**输出为四面体而非原生多面体**。
   另注意：菜单里的「转换为点数据」目前仍用固定 256 缓冲读取单元 id，超大面数的多面体仍有风险。
5. **输出可能大于输入**：相交单元被细分（1→多块）是正常现象；要得到"清晰的等值体"，建议把区间取在能聚焦目标区域的范围，避免过宽的区间。
6. **输出与裁剪粒度**：
   - **纯四面体网格**：输出为原生四面体（已用 `ClipTest` 数据实测：6416/2759、3231/1363）；
   - **含六面体/棱柱/金字塔的混合网格**：按原生单元直接裁剪，输出即为原生单元的组合（六面体 / 楔形 / 金字塔 / 四面体），**不会把单元一律拆成四面体**；
   - 相交单元被细分后**输出单元数可能大于输入**，属正常裁剪行为。
7. **非 ASCII（中文）路径**：上层以 UTF-8 传递路径，而读取层（tinyxml2 的 `fopen_s`、`CreateFileA`/`fopen`）按系统 ANSI 代码页解释、未做 UTF-8 转换，因此**含中文的路径常打不开**，可能导致 `.pvd` 的子文件读取失败。**建议把数据放在纯英文路径**下再使用。
8. **数据规模**：大网格（数十万点/单元）单次提取需要数秒；超大数据建议先裁剪出子区域再导入。

## 7. 数据一致性验证

本 Filter 采用**按单元类型的裁剪 case 表**驱动：对每种单元类型（六面体 / 楔形 /
金字塔 / 四面体）与其顶点的"在区间内 / 在外"组合，直接查表得到**原生单元**组成的
裁剪结果（不把单元一律拆成四面体）。

### 7.1 实测结果

| 测试数据 | 输出单元数 | 输出点数 |
|---|---|---|
| 纯六面体模型（8000 点 / 6859 六面体），标量 ∈ [0.5, 1.0] | **8506** | **5696** |
| 同上，标量 ∈ [0.5, 0.9] | **7738** | **4632** |
| 混合网格（含四面体/六面体/楔形/金字塔），标量 ∈ [0.3, 1.0] | **8757** | **7202** |
| 同一混合网格，标量 ∈ [0.3, 0.5] | **9482** | **7479** |

- **单元类型构成**：输出由四类原生单元组成
  （如纯六面体模型：六面体 2834 / 金字塔 2424 / 四面体 2320 / 楔形 928）。
- **重复性**：同一输入与区间重复执行，输出点数、单元数与单元类型构成保持一致。

### 7.2 已知限制

| 限制 | 说明 |
|---|---|
| 不支持的单元类型 | 二次六面体 / 二次棱柱 / 二次金字塔、Lagrange 等单元的维度为 4，不进入裁剪分支；与等值面相交的这类单元会被**静默跳过**，结果可能不完整且无提示 |
| 点坐标精度 | 点坐标以 **float32** 存储（框架 `Points` 的统一类型），裁剪生成的新交点坐标同样受 float32 精度限制，实测绝对偏差量级约 1e-6（最大约 7.6e-6） |

### 7.3 关键实现要点

1. **裁剪表**：每种单元类型有**两张** case 表 —— 正向（保留 ≥ iso）与反向（保留 ≤ iso），另配一套心点表。键为顶点的符号掩码，值为输出单元定义（单元顶点数代码 + 顶点来源）；**同一掩码下两张表的分解并不互为镜像**，故不能靠取反掩码复用同一张表。
2. **顶点来源编码**：`<8` 原顶点、`8..19` 边插值点、`>=20` 单元内部点。边的合法编号范围随类型不同（四面体 8..13、棱柱 8..16、金字塔 8..15、六面体 8..19）；一个 case 内的多个内部点编号都指向**同一个心点**。
3. **单元内部点（心点）**：等于"表指定的点子集的等权平均"，其属性亦按同一组等权权重插值；若该 mask 下心点表无条目，则回退为"本 case 用到的全部边界点（原顶点 + 边插值点）的等权平均"。
4. **两趟裁剪**：区间 `[lower, upper]` 实现为"先保留 ≥ lower，再保留 ≤ upper"。
5. **完全在内的单元**原样复制，不做任何拆分（单元拓扑与类型不变；后续全局点合并会重排点索引）。
